# 傅里叶变换 · 圆上圆绘图

用「不停旋转的圆」把任意图案画出来 —— 一个纯前端、零依赖的单文件网页应用。

> 灵感来自 B 站「漫士」《[半小时速通傅里叶变换：千年的圆上圆游戏](https://www.bilibili.com/video/BV18Ma96JEoZ/)》

每个圆对应一个傅里叶系数（一个频率）：**半径 = 幅值，转速 = 频率，初始角 = 相位**。把它们首尾相接叠加起来，最后一个圆的笔尖就会画出原图案。

```
路径 → 离散傅里叶变换 → 若干旋转矢量（圆）叠加 → 笔尖轨迹还原原图
```

| 模式 | 适用 | 原理 |
|---|---|---|
| **线稿（中心线）** | 简笔画、线稿、Logo | Zhang-Suen 骨架化取笔画中心线 |
| **轮廓** | 实心图案、剪影、色块 | 前景连通块外轮廓 + 内部孔洞轮廓 |

## 核心原理

### 1. 一个图案 = 一组旋转的圆

把闭合路径 `z(t) = x(t) + i·y(t)` 均匀采样成 N 个点，做离散傅里叶变换：

```
c_n = (1/N) Σ z_k · e^(-2πi·n·k/N)
```

每个非零系数 `c_n` 就是一个圆：

- **半径** = `|c_n|`
- **初始角** = `arg(c_n)`
- **角速度** = `2πn`（n 为频率，可为负 —— 负频表示反向旋转）

在时刻 t，把选中的 K 个系数按幅值从大到小依次叠加：

```
笔尖(t) = Σ_{|n| ≤ K} c_n · e^(2πi·n·t)
```

系数按幅值排序截断，是因为傅里叶系数衰减得快 —— 少数「大圆」记录了主要形状，后面的「小圆」只负责细节。

### 2. 多条独立线条 = 多组圆

每条闭合线条**独立**做傅里叶变换，拥有自己的一组圆和轨迹。关键在于**共同归一化**：

> 所有线条共用同一个中心和缩放系数，而不是各自归一化到 `[-1,1]`。

否则每条线都会被拉伸到同样大小、相对位置全乱。共同归一化后，各条线的**直流项（n=0）自然充当平移圆**，把整组圆搬到正确位置 —— 这也是为什么多层图案能自动对齐。

### 3. 开放笔画怎么用闭合曲线画

傅里叶方法需要闭合曲线。对线段、弧线、箭头这类开放笔画，采用**去程 + 回程**闭合：笔尖沿笔画画过去，再原路画回来。视觉上就是一条线，且不会多出多余的连线。

### 4. 圆数怎么分配

圆数不是平均分的，而是按**复杂度**分配：统计每条线「还原到 98.5% 交流分量能量需要多少系数」，简单笔画少给、复杂轮廓多给。

> ⚠️ 这里有个容易踩的坑：统计能量时**必须排除直流项**。直流项只是平移分量，在远离原点的图形上往往占 99%+ 的能量，若计入会让所有线条都被误判成「很少圆就够」，分配退化成平均。

## 识别参数怎么调

上传图案后如果效果不理想，按这个顺序调：

1. **细节档位**（默认「高」= 120 条线，可选到 400）
   这是提升最大的一项。线稿类图片线条很多（发丝、排线），档位太低会大量丢失。
2. **每条线的圆数**（默认 40，可设到 2048）
   实际会按复杂度分配，总预算上限 20000。设大一些不会浪费。
3. **识别方式**：实心色块请手动切到「轮廓」，线稿用「线稿」。
4. **线条很多时关掉「显示圆」** —— 上万个圆全部绘制会明显掉帧，关掉只看轨迹就流畅了。

### 能"完全还原"吗？

不能 —— 这是傅里叶截断的本质：**圆的个数就是可表达的最高频率**，细节（发丝、排线、反光）都是高频分量，圆数有限就必然有误差（截断 + 吉布斯现象）。要完全精确需要无限个圆，实际要几万个以上。

但可以做到"很像"。实测一张 1376×1632 的铅笔线稿肖像，用 **240 条线 + 19952 个圆**，头发、眼镜、脸型、耳朵、五官都能还原出来（见 `assets/portrait-fourier-preview.png`）。

## 技术实现

**单文件、纯前端、零外部依赖**（约 3000 行 HTML + CSS + JS）。

### 自研的几件事

| 模块 | 说明 |
|---|---|
| **DFT / 重构** | O(N²) 直接计算；采样点数按弧长自适应，并有总开销上限保护 |
| **GIF 编码器** | LZW 压缩 + 中位切分调色板 + 5bit 颜色桶缓存，手写 GIF89a 封装 |
| **Moore 边界追踪** | 区域轮廓提取（注意「来向」方向索引需换算到新像素坐标系） |
| **Zhang-Suen 细化** | 笔画骨架化，供线稿中心线提取 |
| **方向优先贪心走线** | 在骨架交叉点继续直行，把碎线连成完整笔画（125 段 → 19 条） |
| **倒角距离变换** | 判断笔画粗细，用于线稿/轮廓模式自动选择 |
| **橡皮擦** | 路径加密采样 → 标记 → 拆成连续片段 |

### 性能优化要点

- **自适应采样**：采样点数按弧长决定（细节不可能超过像素数），短笔画少采样，让上百条线也能秒级载入
- **渲染跳过**：屏幕半径 < 0.5px 的圆不绘制
- **轨迹隔帧取样**：线条超过 60 条时轨迹隔帧采样，控制每帧折线点数
- **开销上限**：DFT 总开销超过阈值时整体降采样，避免载入卡住

### 实测数据（Node 环境）

| 项目 | 数值 |
|---|---|
| 单线 2048 点 DFT | 114ms |
| 2048 个圆的单帧计算 | 0.12ms |
| 300 条线（含复杂涂鸦）载入 | 741ms |
| 肖像 240 条线识别 + DFT | 950ms + 350ms |
| 300 条线单帧矢量计算 | 0.72ms |

## 常见问题

**Q：打开后一片空白？**
A：检查浏览器控制台。推荐 Chrome / Edge / Firefox 最新版。

**Q：上传图片后画出来是乱线？**
A：多半是圆数被预算压死了 —— 看状态栏的「共 N 个圆」。线稿请把「细节」调到「极高/极限」，并把「每条线的圆数」设大。

**Q：上传后只画出一部分线条？**
A：「细节」档位决定了保留多少条线（标准 60 / 高 120 / 极高 240 / 极限 400），调高即可。

**Q：动画很卡？**
A：关掉「显示圆」，或降低细节档位/圆数。上万个圆同时绘制对显卡负担较大。

**Q：视频导出按钮点了没反应？**
A：需要浏览器支持 `canvas.captureStream` + `MediaRecorder`（Chrome / Edge / Firefox 支持，Safari 部分支持）。

**Q：GIF 文件很大？**
A：GIF 是 256 色调色板格式，复杂图案体积偏大。需要更高质量请用 WebM 视频导出。
